# Промпт: объективная оценка языковых моделей для ИИ-помощника учебной базы

Скопируйте всё, что ниже черты, в чат с моделью, которая будет проводить оценку.
Лучше выбрать модель с доступом к поиску в интернете: цены и лимиты провайдеров часто меняются.

---

## Роль

Ты — независимый инженер по внедрению языковых моделей. Тебе нужно объективно сравнить модели для ИИ-помощника
веб-приложения и рекомендовать, какая из них лучше всего подойдёт именно для этого проекта. Ты не связан ни с одним
провайдером и не должен отдавать предпочтение моделям, которые разработала компания, создавшая тебя самого.

## 1. О проекте

**Что это.** Закрытая учебная веб-платформа (рабочее название — Registry Demo) для работы с учебной базой данных
о военной структуре условных округов Казахстана. Все данные учебные и условные: названия округов, штабы и зоны
ответственности взяты из открытых источников, а состав, численность, техника и запасы смоделированы. Реальных
персональных или секретных данных в базе нет.

**Для кого.** Небольшая группа пользователей (руководитель, разработчики, участники показа) с выданными правами
доступа. Публичной регистрации нет.

**Языки.** Интерфейс на русском. Вопросы к помощнику задают на русском, иногда на казахском.

## 2. Структура данных

Иерархия: **округ → бригада (соединение) → батальон (дивизион) → рота (батарея) → взвод → отделение (экипаж, расчёт)**.
Есть также управление бригады, подразделения бригадного подчинения (разведывательная рота, рота связи, медицинская
рота и т. д.) и подразделения обеспечения батальона (миномётная батарея, гранатомётный взвод, медпункт).

Объём данных (PostgreSQL 16):

| Что | Количество |
|---|---|
| Округа | 4 |
| Бригады | 13 (механизированные, танковая, артиллерийские, обеспечения) |
| Подразделения всех уровней | 2 937 |
| Строки должностей (должность, звание, количество, источник) | 10 154 |
| Строки техники и вооружения подразделений | 7 349 |
| Образцы в каталоге имущества | 327 (370 характеристик ТТХ) |
| Позиции запасов округов (норма, наличие, дефицит) | 280 |
| Общая численность | 13 136 чел. |

У каждой строки есть источник и уровень достоверности: A — факт из открытого источника, B — типовой состав
по открытым источникам, C — оценка составителя.

## 3. Архитектура

- **База данных:** PostgreSQL 16. Сайт читает её через пользователя только для чтения и только через подготовленные
  представления (`registry_api.*`). Права пользователей (к каким округам есть доступ) хранятся в отдельной базе.
- **Сайт:** Django 5.2 (Python 3.12), шаблоны Django, без React. Работает в Docker.
- **ИИ-помощник** — агент с инструментами (function calling):
  1. Модель получает вопрос, список доступных пользователю округов и описания **10 инструментов**:
     `list_districts`, `district_summary`, `district_formations`, `formation_structure`, `unit_composition`,
     `district_equipment`, `district_supply`, `compare_districts`, `find_item`, `item_card`.
  2. Модель выбирает инструменты и параметры (до 4 вызовов за вопрос).
  3. Django проверяет права пользователя и выполняет заранее написанный параметризованный запрос. **Модель не пишет
     SQL и не видит схему базы.**
  4. Вторым обращением модель пишет короткий ответ (1–4 предложения) только по полученным таблицам.
  5. Итоги, максимумы и минимумы, номера и коды подразделений считает код, а не модель. Модель передаёт номера
     («8-я рота», «2-й батальон») или название подразделения, а код собирает программа.
- **Размер запроса к модели:** системная инструкция примерно 3 300 символов, описания инструментов примерно 4 500
  символов, плюс вопрос и таблицы. Это 2 обращения к модели на вопрос, примерно 3–5 тыс. токенов на входе и
  100–300 токенов на выходе в каждом.
- **Подключение модели** сменное, одной настройкой. Сейчас есть модуль для Ollama (локальная модель). Планируется
  универсальный модуль для OpenAI-совместимых API (Groq, xAI Grok, Gemini, OpenAI, Mistral и др.).
- **Запасной режим:** если модель недоступна, работает разбор вопроса по ключевым словам. Страница не падает.
- **Журнал:** каждый вопрос, вызванные инструменты и ответ сохраняются.

## 4. Что уже проверено

Тест из 8 вопросов с правильными ответами из базы на MacBook (Apple M4, 16 ГБ памяти), модели через Ollama:

| Модель | Правильных ответов | Среднее время ответа | Нагрузка |
|---|---|---|---|
| Qwen 2.5 7B (локально) | 5 из 8 | ~7 с | заметный нагрев, ~5 ГБ памяти |
| Qwen 2.5 14B (локально) | 8 из 8 | ~15 с (первый вопрос до 40 с) | сильный нагрев, ~9 ГБ памяти |

Типичные ошибки 7B: неверно собирает уровни подразделения (добавляет лишние «роту», «взвод»), пропускает нужную
строку в таблице, складывает числа сам и ошибается, изредка отвечает по-китайски.

## 5. Ограничения и требования

- Проект планируют перенести на сервер. Параметры сервера пока не выбраны: неизвестно, будет ли видеокарта.
- Помощником могут пользоваться несколько человек одновременно. Очереди и долгого ожидания хочется избежать.
- Бюджет минимальный: предпочтительны бесплатные или очень дешёвые варианты.
- Тема военная, хотя данные учебные. Важно, уходят ли вопросы и данные наружу, где хранятся, используются ли
  для обучения моделей провайдера. Внешние сервисы нужно будет согласовать с руководителем.
- Пользователь находится в Казахстане: важна доступность сервиса и возможность оплаты из Казахстана.
- Обязательно: надёжный вызов инструментов (function calling), хороший русский язык, желательно понимание казахского.

## 6. Задание

Объективно оцени модели и ответь, какая из них будет работать с этой базой наиболее эффективно.

**Кандидаты.** Рассмотри как минимум:

- *Локальные (через Ollama или аналог):* Qwen 2.5 7B / 14B / 32B, Qwen 3 (подходящие размеры), Llama 3.x,
  Mistral Small, gpt-oss-20b, а также другие открытые модели с хорошим вызовом инструментов, если считаешь их
  сильнее.
- *Облачные API:* Groq (открытые модели на их серверах), xAI Grok, Google Gemini, Anthropic Claude (Haiku, Sonnet),
  OpenAI, Mistral, Alibaba Cloud (Qwen), а также GigaChat и YandexGPT как варианты с серверами в России.

**Критерии.** Оцени каждого кандидата по шкале 1–5 и объясни оценку:

1. Точность вызова инструментов: правильный инструмент и параметры, без выдуманных параметров.
2. Качество русского и понимание казахского.
3. Следование инструкциям: отвечать только по таблицам, не придумывать числа, не переходить на другие языки.
4. Скорость ответа (время до готового ответа на вопрос из 2 обращений).
5. Нагрузка на сервер: требования к памяти и видеокарте для локальных моделей; для облачных — нулевая.
6. Одновременная работа нескольких пользователей: лимиты запросов в минуту и в сутки, очереди.
7. Стоимость: цена за 1 млн токенов, бесплатный уровень и его лимиты, примерная цена 1 000 вопросов при
   ~8 тыс. токенов на входе и ~400 на выходе на вопрос.
8. Конфиденциальность: куда уходят данные, используются ли для обучения (отдельно для бесплатного и платного
   уровней), где расположены серверы.
9. Доступность из Казахстана: регистрация, оплата, ограничения по странам.
10. Простота подключения: поддержка OpenAI-совместимого API и function calling.

**Тестовые вопросы.** Для оценки точности используй эти вопросы. Правильные ответы известны:

| Вопрос | Правильный ответ |
|---|---|
| Сколько миномётов в 1-м батальоне ВОС-1? | 6 (120-мм 2С12) |
| Сколько танков в бригаде ЮГ-3? | 62 (54 Т-72Б и 8 Т-72К) |
| Сколько АГС-17 в гранатомётном взводе 2-го батальона ЮГ-1? | 6 |
| Сколько человек в 8-й танковой роте бригады ВОС-1? | 30 |
| Кто командует управлением бригады ВОС-1 и какое у него звание? | командир бригады, полковник |
| Сколько людей в округе Юг? | 4 061 |
| Сравни округа по численности, где меньше всего? | Восток и Запад, по 2 987 |
| Батыста қанша адам бар? (каз.: «Сколько людей на Западе?») | 2 987 |

Если ты не можешь сам прогнать модели, оцени по их известным результатам на тестах вызова инструментов (например,
BFCL — Berkeley Function Calling Leaderboard) и на русскоязычных тестах. Отдельно предложи план, как проверить
2–3 лучших кандидата на этих 8 вопросах.

## 7. Формат ответа

1. **Сводная таблица:** модели × 10 критериев, оценки 1–5 и итоговый балл. Веса критериев укажи явно, по умолчанию:
   точность инструментов ×3, следование инструкциям ×2, русский/казахский ×2, конфиденциальность ×2, остальные ×1.
2. **Тройка лучших** для каждого сценария:
   - а) сервер без видеокарты, бюджет почти нулевой;
   - б) сервер с видеокартой, данные не должны уходить наружу;
   - в) облако, нужна скорость и одновременная работа нескольких пользователей.
3. **Одна главная рекомендация** для этого проекта и запасной вариант на случай, если основной недоступен
   (нет интернета, кончились лимиты).
4. **Риски** выбранного варианта и как их снизить.
5. **Источники** с датой проверки для всех цен, лимитов и условий.

## 8. Правила объективности

- Не придумывай цифры. Если цену, лимит или результат теста не удалось проверить, так и напиши: «не проверено».
- Указывай дату и источник для цен, лимитов и условий использования данных.
- Отделяй проверенные факты от своих оценок.
- Не завышай оценки моделям своего разработчика и не занижай конкурентам.
- Учитывай, что важнее всего надёжность на этой задаче, а не общая «умность» модели.
